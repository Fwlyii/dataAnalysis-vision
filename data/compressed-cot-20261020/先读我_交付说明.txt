四模型回答数据交付说明
生成日期：2026-10-20

一、接收后先看什么
1. 看“数据概况.json”，确认模型、数据量和实验配置。
2. 用 Excel/WPS 的“从文本/CSV 导入”打开“便于清洗/全部回答.csv”。
   编码选择 UTF-8；题目编号、数学表达式、回答、哈希等列按文本导入，
   保留换行和前导字符。CSV 中一条回答可能跨多个物理文本行，请不要按换行拆分。
3. 编程处理或交给 AI 辅助清洗时，优先读取“便于清洗/全部回答.jsonl”。
   每个物理行是一条 JSON 对象，record 内保留保存时的完整回答记录。
4. 优先复核“便于清洗/待复核回答_请在副本填写.csv”。
   其最后五列留空供填写；原始评分列保持不动。
5. 已生成的图表在“原始结果/<运行目录>/analysis/<模型>/<数据集>/对比图.png”，
   同目录有 PDF、SVG；analysis/提示词对比.csv 是提示词级汇总表。
   这张汇总表不是逐题回答，不能只交付它来开展清洗。

二、数据范围
模型：DeepSeek（deepseek-flash）、Qwen2.5-7B-Instruct、Qwen3-8B、Hy4-preview。
每个模型：3 个数据集 × 每数据集 200 道题 × 31 种提示词 = 18,600 条回答。
合计：74,400 条回答，独立题目是共同的 600 道，不是 74,400 道不同题目。
数据集：MMLU-Pro 数学、GSM8K、MATH500。
四个模型的题目、选项、标准答案、题目顺序与提示词已核对一致。
当前回答无接口失败项或缺失项；这不代表全部回答正确。
temperature=0，max_tokens=800，seed=91（seed 用于数据抽样）。
本次是每数据集 200 题的替换模型实验；不能写成每数据集 500 题的原论文完整配置复现。
题目来源、版本和选取信息在 manifest.json/datasets 中；其中“前500题”描述缓存池，
实际本次清单 questions 只有每数据集 200 道题，以清单内容为准。
DeepSeek、Qwen3、Hy4 的关闭思考参数以清单中的 extra_body 为准；
Qwen2.5 未配置独立的思考模式开关。
不同模型的 token 来自各自 API 统计，token 数不等于字符数，各模型分词器可能不同。

三、交付目录
原始结果/：逐字节复制的 manifest.json、分模型分数据集回答 JSON、分析文件；
             DeepSeek 另带扩充来源与离线重评分/复核记录。
便于清洗/：全量 CSV、全量 JSONL、待复核 CSV、共用题目和共用提示词。
评分与分析参考源码/：当前项目的离线评分、分析逻辑与依赖清单，供理解统计口径。
数据概况.json：数量和版本信息。
校验交付包.py、SHA256SUMS.txt：检查传输完整性和数据量。
只阅读或清洗数据无需 API Key，也无需安装模型。
本包未包含 .env.local、平台密钥、虚拟环境、Git 仓库、运行日志、费用账本或未完成的 Kimi 数据。
manifest.json 保持原样，包括 API 密钥的环境变量名称；环境变量名称不是密钥。
DeepSeek 原始扩充清单自带历史费用摘要，其存在是为了保留原始实验身份。

四、主要字段（原始 JSON/JSONL）
唯一定位一条回答：model + benchmark + prompt_id + question_id。
record_id/CSV“记录编号”：上述四个标识拼接；清洗时不要改动。
question.question：题目原文；question.options：选项；question.answer：标准答案。
prompt_text：实际实验提示词原文；不翻译或改写这些实验输入。
record.text：模型原始可见回答，包含解题过程（如模型输出了过程）。
record.reasoning_text：平台独立返回的推理字段，空字符串不代表可见回答没有解题过程。
record.answer：从回答中提取的最终答案；不是标准答案。
record.grade：当前保存的评分，1 为判对，0 为判错；尚需结合复核清单核验。
record.status=ok：API 调用和保存成功，不代表答对。
record.token_count：API 返回的输出词元数。
record.input_tokens、reasoning_tokens、answer_tokens：平台提供的相关统计；
  JSON 的 null 表示未提供，不能一律当作 0。CSV 对 null 输出空单元格。
record.usage：完整保留的 API 用量字段。
record.truncated：是否因输出长度限制截断。
record.needs_review：原评分器的待复核标记。
included_in_review/CSV“纳入复核清单”：needs_review 或 truncated；
  因此 needs_review=false 的截断回答也可能在清单中。
record.original_grading、grading_revision、grading_review：如存在，表示保存的评分修订来源。
source_file：对应原始回答 JSON 的包内相对路径。
record_hash：整个 record 的稳定指纹，用于确认原始记录是否被改动。
JSONL 另外补齐了题目和提示词，record 本身与对应原始文件中的记录完全一致。

五、清洗与复核任务建议
待复核共 3,920 条：DeepSeek 797，Qwen2.5 709，Qwen3 987，Hy4 1,427。
这些条目包括截断、最终答案提取失败或格式不明确；不等于全都是错误回答。
先处理清单，再抽查未标记记录。AI 可辅助提取与解释，但不要把它的判断直接当标准答案。
请保留原始数据副本；在工作副本或单独修订表中进行清洗。
不要为了提高准确率删除错误、截断或难以解析的回答。
不要覆盖原始回答、标准答案、题目/提示词身份和 API token 数。
提取更简洁的最终答案后，也不要用该答案的长度替换模型原始输出 token 数。
复核后记录：原记录编号、原评分、新评分、提取答案、复核者、时间、理由。
新评分仅在能够判断时填写 0 或 1，无法确定时留空并写明原因。
DeepSeek 已存在一次离线重评分及保存的逐条复核；其余模型保留本次运行评分。
四个实验的代码指纹不同，不能仅凭本交付包就声称它们从始至终使用完全相同的评分版本。
参考源码是交付时版本，未自动对四组数据再次统一重评分。
若统一修订评分规则，应在四个模型的工作副本上使用同一规则，并保留变更日志。
现有图表是当前评分下的结果；清洗后要重新计算统计，不要把新评分与旧图表混用。
阈值、预测准确率和理想分配曲线来自同一批数据的拟合，不是独立测试集泛化结果。

六、建议对方交回什么
1. 清洗后的完整数据副本，保留 74,400 条记录及稳定记录编号。
2. 逐条修订表：原评分、新评分、修改理由、复核者、时间。
3. 清洗报告：规则、修改数量、未解决条目、对准确率和图表的影响。
只交回“清洗后的准确率”无法追溯修改来源。

七、可选的完整性校验
有 Python 3 时，在本目录运行：
  python 校验交付包.py
该脚本只读取本包，不联网、不调用 API、不修改数据。
校验文件记录包内各文件 SHA-256；SHA256SUMS.txt 自身不包含在其清单中。
若对工作副本作了有意修改，原哈希校验会不一致，应保留未经改动的交付原包。
