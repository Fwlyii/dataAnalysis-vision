# 课堂展示顺序

建议按十分钟组织讲解。首页使用知微五气泡，进入章节后只用顶部五章导航；核心发现始终在同一长页向下滚动。讲述围绕问题、处理过程和证据展开，不需要逐图点击、播放、切换筛选或展开说明。

1. **研究问题**：从“同一任务，怎样提示更有效”进入数学、文档问答、Python代码三类任务。页面同时显示三组真实案例：回答语言、证据位置、执行反馈分别改变了什么。
2. **采集设计**：说明四个策略维度与31种实际提示，强调同题比较；再交代文档位置和代码反馈的专项控制。四维是标签，不是把所有条件做成完整笛卡尔组合。
3. **数据处理**：停留在一张完整静态Figure上，从A看到D。指出两种来源里含义相同但字段名不同的红色字段，沿映射看到两条统一记录，最后落到统一21列CSV保存格式。所有来源、映射和结果同时可见，无需切换按钮。物理响应、专项子集、重复测量与共享初稿分别计数。
4. **核心发现**：用最长时间沿页面滚动，先总后分。四个总体主题依次是Token投入与成功率的边际收益、模型规模、简洁思考、收紧限制后的输出反弹；随后进入数学中英文、文档证据位置和代码反馈三个专项。每个主题选主图讲清横纵轴、对照条件和结论，辅助图已经完整排在后面，用于支撑解释，无需逐张操作。原37张图不删减。
5. **总结与反思**：回到如何分配输出、组织证据和使用反馈，交代研究范围与后续改进。页面切换与动效服务叙述，答辩主线不进入图稿资源页。

代码反馈补充批次只有在真实采集与强测完整后才加入第四步，讲解顺序为：

- 先读独立题数、每题每模型三份初稿、六条反馈策略及实际有效响应数；HTTP重试单独报告，不把程序份数当成独立题目数。
- 分清模型看得到的公开诊断与不进入反馈的强保留测试。先看初稿／终稿强测，再对照公开轨迹和离线强测轨迹，核对图内真实题目分母。
- 同时解释初错修复和初对回退，再看Token代价。按模型读配对差值与95%区间；区间跨0时，明确表示尚不支持稳定提升。
- 顺着一条真实案例读“修改前代码→实际反馈→修改后代码→公开与保留结果”。未测试的版本保持未测，没有观测到的错误类别不补造案例。
- 最后单独看旧Mini终稿的完整强复核。旧代码没有重新生成，结果不并入新批；公开重执行差异与旧超时未复现分别解释。

图稿准备与课堂讲解分开进行。可编辑SVG和CSV保存在原图包与独立补充图包中；`?chapter=atlas`用于提前取材，不属于这条展示路线。正式讲解不使用左右方向键跳章、九位置滑块、五版本播放、逐图导出菜单或按需展开；这些都不是当前答辩长页的交互。
