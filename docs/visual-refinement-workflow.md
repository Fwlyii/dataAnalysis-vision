# 前端维护流程

## 修改前

检查工作区和真实入口，保护用户修改。网站只有 `app/index.html` 与 `app/explore.html` 两个入口，但包含93个受检路由/筛选状态。清单由 `tests/browser/inventory.mjs` 从真实章节、模型、图表枚举和代码视图导出，不能只检查首页。

## 设计与实现

沿用深海蓝、雾蓝灰、冷白和少量香槟金，保持原开场与五球交接。科研图表继续使用原数据、路径、坐标、比例、字体和颜色语义。交互增强位于独立模块，优先复用本地Motion mini，不将装饰图或生成稿当作真实数据。

确有审美不确定时可以生成视觉参考，但不必在仓库归档每轮设计截图和视频。只保留实际采用的运行时素材、来源与许可证。研究表格、图表与文字维持可交互、可导出的真实实现。

## 检查

执行构建、快照检查、静态保护检查和浏览器回归。核心覆盖包括五章、五项发现、全部全貌条件、13类图表、4个代码子视图、更多发现、真实空状态、CSV/SVG导出、键盘和减少动态效果。

发布检查使用 `tests/run.py` 的当前93状态操作；全量检查使用 `--full`，保留五种电脑宽度巡检及逐项交互。测试输出统一到忽略的 `artifacts/qa/`；默认不保存截图、不录制视频。

`tests/fixtures/`只保留小型源码/数据保护清单、真实科学图对照摘要和代表性导出基线。历史科学图结构、样式和像素对照绑定原生产源码；源指纹变化时必须先评审与复测，不能直接改哈希消除失败。科研数据和图稿的1,100文件保护继续有效。

## 发布

按用户授权正常推送main。Pages在构建后检查科学/源码契约，并实际运行浏览器测试后再次核对其源指纹，成功才发布。录屏和历史截图不是发布依赖。

历史设计流程与大文件按用户要求从工作区移除，整理前提交为 `c3d648a`。本轮整理不改变现用页面或科学图表。
